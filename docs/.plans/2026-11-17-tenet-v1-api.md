# tenet v1: public API

## Context

This is a sub-plan of the [tenet v1 plan](2026-11-17-tenet-v1.md). It writes tenet's exported API as Go declarations
with their doc comments, so that the API can be reviewed as `go doc` shows it before anything is built behind it. Each
exported function and method has the body `panic("not implemented")`, and the exported types have no fields yet.
Nothing unexported is written, and there are no tests. The parent plan's **Both sides, in Go** task implements and
tests this API.

The terms are the parent plan's: initiator, acceptor, dialer, listener and tunnel, and "connect" for the WebSocket and
"dial" for the connections inside it. The `Dialer` type is the dialer's side of one tunnel.

The main entry points come first. Configuration, that is the liveness settings and the backoff, comes in a second
task, once the entry points are approved.

It needs the parent plan's Setup task first, because `doc.go` and `go.mod` still hold the template's placeholders.

## Decisions

### The acceptor's side
- `func Accept(w http.ResponseWriter, r *http.Request) (*Dialer, error)`. The acceptor's handler calls it after it has
  admitted the initiator. If the upgrade to a WebSocket fails, Accept has already written an HTTP error response to `w`,
  and returns an error. The `*Dialer` doesn't depend on `r.Context()`, so it lives on after the handler returns.
- `Dialer`'s doc comment: "A Dialer dials connections to an initiator's listener through one WebSocket." Each
  WebSocket gets its own `*Dialer`, so when an initiator connects again, Accept returns a new one.
- `func (d *Dialer) Dial(ctx context.Context) (net.Conn, error)` opens a new connection to the listener. It has no
  network or address, because there is only one listener to reach. It returns an error that wraps `ctx.Err()` as soon
  as `ctx` ends, an error that wraps `d.Err()` once the WebSocket has ended, and an error at once if the listener is
  closed.
- `func (d *Dialer) Done() <-chan struct{}` returns a channel that is closed when the WebSocket ends.
- `func (d *Dialer) Err() error` returns nil until the channel from Done is closed, and then why the WebSocket ended. It
  returns `net.ErrClosed` if `d.Close` ended it.
- `func (d *Dialer) Close() error` ends the WebSocket and every connection on it. It may be called more than once, and
  returns nil; it returns an error only so that `*Dialer` is an `io.Closer`.

### The initiator's side
- `func Listen(ctx context.Context, client *http.Client, url string, header http.Header) (*Listener, error)` returns at
  once, and connects to the acceptor in the background, and again whenever the WebSocket ends. It returns an error only
  if `url` doesn't parse or its scheme isn't `https`, because the parent plan's Transport section allows only a secure
  WebSocket. It sends a copy of `header` with each attempt to connect; a value that changes between attempts, such as a
  token, belongs in `client`'s `Transport`.
- `ctx` lives as long as the listener. Cancelling it ends the WebSocket and every connection at once, and stops the
  listener connecting again.
- `Listener`'s doc comment: "A Listener accepts the connections that an acceptor dials through the WebSocket that
  Listen connects." `*Listener` implements `net.Listener`.
- `func (l *Listener) Accept() (net.Conn, error)` waits for the next connection that the acceptor dials, across
  WebSockets. It returns `net.ErrClosed` after `l.Close`, and an error that wraps `ctx.Err()` once `ctx` is cancelled.
  It reports no other error, so a WebSocket that ends doesn't stop a server that is serving the listener. Why each
  WebSocket ended, or why an attempt to connect failed, goes to the backoff function, in the configuration task.
- `func (l *Listener) Close() error` stops the listener connecting again. No new connections open, the dialer's new
  dials fail at once, existing connections are left to the application, and the WebSocket ends after the last one
  closes. It returns nil.
- `func (l *Listener) Addr() net.Addr` returns an address whose `Network` method returns `"tenet"`.

### What the doc comments promise about connections and addresses
- The connections that `Dial` and `Accept` return are `net.Conn` values, with deadlines as `net.Conn` requires. The doc
  comments promise nothing more about them, such as half-close.
- Every address, from `Listener.Addr` and from each connection's `LocalAddr` and `RemoteAddr`, has the network
  `"tenet"`. Its `String` method describes the far end of the WebSocket for display, and its format is not part of the
  API.

### Package documentation
- It starts with the README's first sentence, defines the parent plan's terms, states the fixed bounds, says that tenet
  doesn't log, and sketches each side's use without naming a protocol that runs over tenet.
- The bounds, 256 connections waiting for the listener and 256 KB per connection in each direction, are stated there,
  not as exported constants, so that no code depends on them.

## Delivery order

Tick each item when it is done, and write the pull request or commit that did it beside it.

- [x] **Entry points**: the exported declarations and doc comments for both sides, with `panic("not implemented")`
  bodies. `doc.go` holds the package documentation. `accept.go` holds `Accept`, and `Dialer` with `Dial`, `Done`, `Err`
  and `Close`. `listen.go` holds `Listen`, and `Listener` with `Accept`, `Close` and `Addr`. The liveness settings and
  the backoff are left out of the signatures until the next task.
- [ ] **Configuration**: one type for the liveness settings, an interval and a timeout, which `Accept` and `Listen` both
  take, and one function type for the backoff, which `Listen` takes. Both are required arguments with no defaults, and
  `Accept` and `Listen` return an error if a setting is not positive. The backoff function is given why the last
  WebSocket ended, or why the last attempt to connect failed, and returns how long to wait before connecting again.
  Their names are chosen first, from the candidates under Open.

Each task ends with `go build ./...` and `go vet ./...` passing, and `go doc -all .` read through as a user would.

## Open
- The name of the liveness settings type. The candidates, recommended first:
  - `Liveness`, as the parent plan calls them: "Liveness says how a side of a tunnel notices that the other side has
    stopped answering."
  - `Keepalive`: "Keepalive says how a side of a tunnel notices that the other side has stopped answering."
  - `Heartbeat`: "Heartbeat says how a side of a tunnel notices that the other side has stopped answering."
- The name of the backoff function type, `func(n int, err error) time.Duration`, where `n` counts calls since a
  WebSocket was last established, starting at 1. The candidates, recommended first:
  - `Backoff`: "Backoff returns how long the listener waits before it connects again."
  - `Reconnect`: "Reconnect returns how long the listener waits before it connects again."
  - `RetryPolicy`: "RetryPolicy returns how long the listener waits before it connects again."
